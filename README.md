# by:Chaildy

Telegram-бот для заявок на тату и адаптивный сайт для согласования стиля. Сайт публикуется на GitHub Pages. Бот запускается отдельно на компьютере или сервере; GitHub Pages Python не исполняет.

## Что готово

- Отдельное согласие на обработку данных и подтверждение 18+.
- Пять обязательных ответов: имя, идея, место, размер, удобные дни.
- Необязательные бюджет и до трёх фото референсов.
- Проверка и изменение каждого ответа перед отправкой.
- Сохранение черновиков и заявок в SQLite, одна активная заявка на клиента.
- Команды мастера, назначение и перенос сеансов с проверкой пересечения интервалов.
- Уведомления через устойчивую очередь, напоминания за 24 и 2 часа при достаточном времени до сеанса.
- Отмена, отзыв согласия, удаление из базы и попытка удаления копий уведомлений в Telegram.
- Очистка незавершённых анкет через 7 дней, заявок после заданного срока.
- Тёмный фиолетовый сайт, декоративные карты с луной, звёздами и свечами в SVG, пустой каталог, FAQ и пример анкеты без ввода реальных данных.

Фото работ, реальный адрес, цены и биография мастера не выдуманы. Каталог сейчас пустой. Админ-панель загрузки эскизов отложена до утверждения стиля.

## Быстрый старт бота: Windows

Python 3.13 или 3.14. Команды из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe -m bot.main
```

Если `.env` уже существует, не копируйте шаблон поверх него. Токен введите только в локальный `.env`, без отправки в GitHub или публичную переписку.

1. Создайте бота через [@BotFather](https://t.me/BotFather). Укажите токен в `BOT_TOKEN`.
2. Запустите бота, отправьте ему `/start` и `/id` с аккаунта мастера. Введите полученный числовой ID в `ADMIN_IDS`. Можно несколько через запятую.
3. Заполните `MASTER_TELEGRAM` без `@`, город, сведения оператора и контакт для отзыва согласия.
4. Перед реальными анкетами согласуйте документы и обработку через Telegram, размещение БД и уведомления оператора. См. [docs/privacy-launch.md](docs/privacy-launch.md).
5. После согласования установите `PRIVACY_READY=true` и перезапустите процесс.

Каждый администратор должен первым открыть бота и отправить `/start`, иначе Telegram не разрешает боту писать ему. При неверных или незаполненных сведениях оператора сбор анкет закрыт, но `/id`, меню и справка доступны.

## Команды

Клиент: `/book`, `/my`, `/faq`, `/prepare`, `/contact`, `/privacy`, `/cancel` (удалить черновик), `/delete` (отозвать согласие, удалить данные и отменить запись).

Мастер: `/admin`, `/bookings`, `/view ID`, `/confirm ID ГГГГ-ММ-ДД ЧЧ:ММ МИНУТЫ`, `/decline ID`, `/cancel_booking ID`, `/done ID`.

`/confirm` также переносит существующий сеанс и заменяет напоминания. Длительность обязательна для проверки пересечений. Время интерпретируется в `TIMEZONE`, по умолчанию `Europe/Moscow`.

Дату, длительность, цену и условия оплаты мастер согласует с клиентом лично **до** команды `/confirm`. Бот не принимает деньги и не объявляет заявку бронью до подтверждения. Фото доступны мастеру по `/view ID`. Активные заявки показываются по 20 последних, любая известная заявка открывается через `/view`.

## Постоянный запуск

Компьютер должен оставаться включённым и подключённым к интернету. Для круглосуточной работы нужен отдельный сервер с постоянным диском, выбранный после согласования обработки данных.

```sh
docker compose up -d --build
docker compose logs --tail=50 bot
```

SQLite лежит в именованном томе `bot-data`. Запускайте только **один** экземпляр бота: один polling-процесс и одна БД. Контейнер работает без root, корневая файловая система только для чтения. Исходящие обращения к Telegram идут по HTTPS; открытые входящие порты не требуются. Docker-сборка не проверялась в этой среде, проверьте её на выбранном сервере.

Бэкап БД содержит персональные данные: ограничьте доступ, задайте сроки хранения и порядок удаления. Для согласованного бэкапа используйте SQLite backup API, а не копирование открытого файла. Автоматическое удаление в рабочей БД не удаляет старые резервные копии само по себе.

## Сайт

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory site
```

Открыть `http://127.0.0.1:8765`. До подключения бота кнопки открывают пример анкеты с вымышленными ответами. После получения имени бота заполните `site/config.js` → `botUsername`, при необходимости `city`. Поле `MASTER_TELEGRAM` бота настраивается отдельно в `.env`.

Публичный конфиг никогда не должен содержать токен, административные пароли или клиентские данные. Шрифты размещены локально с лицензией OFL. Сайт не подключает аналитику, внешние шрифты и cookies. Прототип не собирает заявки в GitHub.

Декоративные SVG-карты масштабируются по `viewBox`, текст и секции остаются HTML/CSS. Вёрстка перестраивается по ширине экрана, фотографий в качестве основы макета нет. Внизу главной страницы и страницы персональных данных размещена плашка автора «by alaron» со ссылкой на его GitHub.

Будущий каталог читает `site/content/gallery.json`. Пока это `[]`. Формат карточки описан в [docs/admin-next.md](docs/admin-next.md). Возможность чтения каталога уже подготовлена, загрузка мастером через админ-панель **ещё не реализована**.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q bot
node --check site/app.js
```

29 проверок покрывают анкеты, согласие, сохранение после перезапуска, пересечения, перенос, очередь уведомлений, права мастера, команды Telegram и удаление при конкурентной отправке. В тестах Telegram API имитируется. Реальный обмен Telegram требует токена и двух тестовых аккаунтов.

Для браузерной проверки установите Playwright в среде разработки и браузер Chromium: `npm install --no-save playwright`, `npx playwright install chromium`. `node scripts/verify_site.cjs URL` проверяет 320, 390, 768, 1280 и 1920 px; в Windows используется установленный Edge. Результаты и скриншоты сохраняются в игнорируемом `artifacts/`.

GitHub Actions выполняет проверки исходников; отдельный workflow публикует только `site/`.

Исследование и продуктовые решения: [docs/market.md](docs/market.md). План живой проверки: [docs/acceptance.md](docs/acceptance.md).
