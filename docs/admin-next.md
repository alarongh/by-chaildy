# Следующий этап: кабинет мастера

Сейчас сайт читает пустой `site/content/gallery.json`. Клиентские заявки хранятся только у бота. В коде нет фиктивного входа администратора, браузерного «секретного пароля» или публичной формы загрузки без защиты.

После утверждения стиля нужен отдельный backend: учётная запись мастера, защищённая сессия, загрузка изображений с проверкой размера и типа, генерация миниатюр, создание/редактирование/скрытие карточек, статус эскиза и публикация каталога. Секреты остаются на сервере. Никаких административных токенов в `site/config.js`.

Формат публичной карточки:

```json
{
  "id": "sketch-001",
  "title": "Название, указанное мастером",
  "description": "Описание мастера",
  "image": "./uploads/sketch-001.webp",
  "available": true,
  "published": true
}
```

До backend каталог можно заполнить вручную через Git. Данные карточек вставляются как текст, изображения ограничены ресурсами своего сайта, SVG от пользовательских загрузок не разрешаются. Сейчас CTA карточки переводит в общий бот; перед запуском каталога добавить `start=sketch_ID` и перенос ID эскиза в анкету. Статус «занят» блокирует кнопку карточки, но не является серверной блокировкой сделки: это нужно реализовать в backend.

В кабинет нельзя выводить заявки на публичных страницах GitHub Pages. Если сайт остаётся статическим, backend и хранилище будут отдельными. Возможность запуска админ-панели, её публикация и проверка прав входят в следующий этап.
