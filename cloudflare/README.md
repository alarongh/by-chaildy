# Бесплатный облачный запуск by:Chaildy

Cloudflare Workers Free + один Durable Object с постоянной SQLite. Компьютер не нужен для обработки сообщений. Бот работает через защищённый Telegram webhook, напоминания и повторная доставка через Durable Object Alarms.

Тариф проверен по [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) и [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/). Free включает до 100 000 запросов в день, 5 ГБ общего SQL-хранилища, 5 млн чтений и 100 000 записей строк в день. Есть также лимиты CPU и длительности работы. При превышении бесплатных лимитов операции останавливаются; платные подписки скрипт не создаёт. Не переключайте аккаунт на Workers Paid.

## Что сохраняется

Согласие, пять ответов, необязательные бюджет и фото, черновики, статусы, команды владельца, просмотр анкет, отмена и удаление, напоминания, проверка пересечений времени. Два администратора задаются локальным `.env`. Уведомления мастеру содержат кнопку открытия анкеты.

Webhook проверяет секретный заголовок Telegram. Повторный `update_id` не создаёт вторую анкету и второй ответ. Изменение формы и постановка ответа в очередь выполняются одной транзакцией. Неполученные ответы повторяются, база сохраняется при перезапуске. Обработка отправок, просмотра и удаления сериализована. В публичном `/health` нет анкет и секретов; импорт и состояние базы требуют отдельного секрета.

## Запуск

1. Войти в личный Cloudflare аккаунт и завершить авторизацию CLI. Регистрацию, коды, CAPTCHA и принятие условий выполняет владелец аккаунта. Карта и платный тариф не нужны для выбранной архитектуры.
2. Из папки `cloudflare` выполнить `npm ci`, `npm run build` и `npm test`. `node node_modules/wrangler/bin/wrangler.js login` открывает авторизацию CLI.
3. Из корня проекта выполнить `.\.venv\Scripts\python.exe scripts/cloudflare_deploy.py auth-check`. Проверяется доступный аккаунт и отсутствие платной Workers-подписки. Если аккаунтов несколько, указать выбранный `CLOUDFLARE_ACCOUNT_ID`. Ограниченная авторизация Wrangler может запрещать чтение подписок (HTTP 403). В этом случае сначала проверить в панели `Workers plans`, что у Free ($0) отмечен `Current plan`, и сохранить приватное подтверждение в `data/cloudflare-plan-verification.json`: поля `account`, `plan: "free"`, `source` (точный URL `https://dash.cloudflare.com/ACCOUNT_ID/workers/plans`) и `verified_at` (Unix timestamp проверки). Такое подтверждение принимается только для того же аккаунта, в течение часа и только при HTTP 403. Старое подтверждение не разрешает новую публикацию.
4. Выполнить `.\.venv\Scripts\python.exe scripts/cloudflare_deploy.py deploy`. Токен и настройки передаются в secret bulk по stdin. Они не попадают в исходники, аргументы процессов или GitHub. До переключения облачный сервис не принимает анкеты, локальный бот работает.
5. Выполнить `.\.venv\Scripts\python.exe scripts/cloudflare_deploy.py cutover`. Скрипт проверяет облачную конфигурацию, останавливает только подтверждённый процесс этого бота, сохраняет приватную резервную копию, импортирует все записи, сравнивает количества и включает webhook без потери ожидающих сообщений. Затем проверяет webhook и `/health`.
6. Проверить реальные `/book`, `/bookings`, просмотр, отмену и удаление с клиентского аккаунта. Владельцу нужно предварительно отправить `/start`.

`data/cloudflare-runtime.json` и резервная копия `data/cloudflare-migration.sqlite3` приватны и исключены из Git. Не запускайте локальный polling параллельно с облачным webhook. Исходный Python-бот при существующем webhook откажется от запуска.

Если переключение прервётся после остановки локального процесса, `cutover` можно повторить: этапы записываются приватно, повторный импорт не выполняется. Не запускайте локальный бот и не удаляйте webhook до проверки записанного этапа, чтобы не смешать изменившиеся базы. Не выполняйте откат из старой копии после появления новых облачных заявок.

## Обновления и проверки

Тексты экспортируются из Python-версии командой `.\.venv\Scripts\python.exe scripts/export_cloud_content.py`. После изменений облачного кода: `npm run build`, `npm test`, затем `deploy` (без повторного `cutover`).

17 тестов покрывают клиентскую анкету, согласие, возраст, владельца и ограничения просмотра, повторную отправку, редактирование, фото, интервалы и напоминания, удаление, сроки, импорт и транзакции. Один из них запускает настоящий Worker runtime Miniflare с SQLite и подставным Telegram API; это не заменяет проверку опубликованного сервиса с реальными пользователями.

Рабочая публикация 6 октября 2026 года: `https://by-chaildy-bot.nna-nikita2007.workers.dev`. Free ($0) подтверждён в панели аккаунта. База перенесена, Telegram webhook включён, `/health` возвращает `active: true`, локальный polling остановлен. На момент проверки очередь Telegram пуста, ошибок webhook нет. Оба администратора доступны боту. Новые заявки принимаются независимо от компьютера; `/admin` и `/bookings` доступны владельцу и администратору проекта.
